## 3. Модель

Клас `Training(ABC)` (`models.py`) зберігає `date, kind, duration, distance, pulse`.

- **`__init__`** призначає поля через властивості (`self.kind = kind`), тож правило перевірки
  існує в одному місці — setter-і; некоректний об'єкт створити неможливо.
- **`@property` + setter:** `kind` (непорожній, `strip`), `duration` і `pulse` (ціле, `>= 0`, `bool`
  відхиляється), `distance` (число, скінченне, `>= 0`). Setter записує у **внутрішнє поле**
  `_kind`, а не у властивість: інакше присвоєння викликало б setter нескінченно (рекурсія).
  `date` — лише читання (немає setter-а).
- **Типи помилок:** хибний тип — `TypeError`; хибне значення — `ValueError`. Loader перетворює
  обидва на `DataError` із номером рядка й першопричиною в `__cause__`.
- **`load()`** — абстрактний метод: `Training` не створюється напряму.
- **Спеціальні методи:** `__str__` (для читача: `2026-09-01, Біг: 45 хв, 7.50 км, пульс 148`),
  `__repr__` (діагностичний, з назвою класу), `__eq__` (однаковий точний клас і всі поля; для
  чужого типу повертає `NotImplemented`, тож `==` дає `False`), `__lt__` (дата, потім вид).
- **`__hash__ = None`:** об'єкт змінюваний (є setter-и) і має `__eq__`, тому не хешується — зміна
  поля «загубила» б його в множині чи словнику.

Впорядкування реалізовано `__lt__` (потрібне для `sorted(list_of_trainings)`); для разового
сортування за іншою ознакою доречніше `key=`, щоб не вшивати один порядок у клас.

## 4. Dataclass

```python
@dataclass(frozen=True)
class KindLoad:       kind: str; count: int; total_load: float
@dataclass(frozen=True)
class ReportSummary:  total, selected, kinds, selected_minutes, selected_distance,
                      distance_by_kind, average_pulse, longest, load_by_kind
```

`@dataclass` сам створює `__init__`, `__repr__`, `__eq__`; `frozen=True` забороняє присвоєння
атрибутів (`FrozenInstanceError`) й дозволяє хешування. Підсумок — **значення**, а не сутність зі
станом: його будує `analysis.summarize`, а `reporting` лише читає. Колекції в підсумку — кортежі
(`kinds`, `distance_by_kind`, `load_by_kind`), інакше «заморожений» об'єкт можна було б змінити
зсередини. Обрано `dataclass`, а не `Training`-подібний клас, бо тут немає перевірок і поведінки,
лише дані.

## 5. Підтипи та протокол

| Підтип | Коли створюється | Формула `load()` | Приклад |
| --- | --- | --- | --- |
| `Running` | усі види, крім велосипеда | `duration × pulse / 100` | 45 хв, пульс 148 → 66.60 |
| `Cycling` | вид «Велосипед» (без урахування регістру) | `distance × 3 + duration / 10` | 28.4 км, 90 хв → 94.20 |

Вибір підтипу виконується **один раз**, у фабриці `loader.build_training`; далі код працює зі
спільним типом. `analysis.load_by_kind` просто викликає `workout.load()` — формулу знає підтип
(поліморфізм). У модулі `analysis` немає ні `isinstance`, ні назв `Running`/`Cycling` (це перевіряє
тест `test_analysis_source_has_no_type_checks`).

`Workout` — `typing.Protocol` (`@runtime_checkable`): властивості `date, kind, duration, distance,
pulse` і метод `load()`. **Качина типізація:** тип не зобов'язаний успадковувати `Training` — досить
мати ці члени; тест передає в усі функції аналізу сторонній клас `Duck` без спільного предка, і
аналіз працює без змін. `super()` і MRO у моделі не потрібні: підтипи не перевизначають
`__init__`, тому ланцюг викликів тривіальний (`Running → Training → ABC → object`).

## 12. Відповіді на контрольні питання

1. **Клас** — опис (шаблон) типу, **екземпляр** — конкретний об'єкт цього типу зі своїм станом.
2. **`__init__`** ініціалізує щойно створений об'єкт; **`self`** — посилання на цей екземпляр,
   через яке методи звертаються до його полів.
3. **`@property`** робить метод доступним як атрибут і дає місце для перевірки або обчислення
   без зміни синтаксису `obj.x`.
4. **Setter пише у внутрішнє поле** (`_x`): запис у саму властивість знову викликав би setter —
   нескінченна рекурсія.
5. **`@dataclass`** автоматично додає `__init__`, `__repr__`, `__eq__` (і за потреби
   впорядкування, `__hash__`) за анотаціями полів.
6. **`frozen=True`** забороняє змінювати атрибути після створення (`FrozenInstanceError`),
   робить об'єкт значенням і дозволяє його хешувати.
7. **`__str__`** — зрозумілий текст для користувача; **`__repr__`** — однозначне діагностичне
   подання (бажано таке, що відновлює об'єкт).
8. **`__eq__` для несумісного типу** повертає `NotImplemented`, а не `False` і не виняток —
   Python спробує дзеркальний метод, а в підсумку `==` поверне `False`.
9. **`key=`** краще, коли порядок потрібен лише в конкретному місці або їх кілька; `__lt__`
   вшиває один «природний» порядок у клас, тож виправданий, лише якщо такий порядок очевидний.
10. **`super()`** повертає проксі для наступного класу в MRO, щоб викликати базову реалізацію
    (наприклад, `__init__`) без жорсткого зазначення предка.
11. **MRO** — порядок пошуку методів у ієрархії (лінеаризація C3). Його треба враховувати при
    множинному успадкуванні: від нього залежить, який метод буде викликано.
12. **Качина типізація:** важить не успадкування, а наявність потрібних членів — «якщо ходить як
    качка…».
13. **`Protocol`** описує такий контракт явно (для читача й перевірників типів) без примусового
    успадкування, тому узгоджується зі сторонніми класами.
14. Бо розгалуження за підтипом у кожній функції змушує змінювати аналіз при кожному новому
    підтипі; поліморфний виклик `load()` залишає знання про формулу в самому підтипі.
15. **На межі завантаження — у `loader`:** він єдиний знає про словник/рядки CSV; далі код
    працює з об'єктами й не повторює розбір.
16. Бо імпорт має бути без побічних ефектів: інакше тести, інші модулі й документація
    запускали б програму; точка входу — `main()` під `if __name__ == "__main__"`.
17. **Тести перевіряють:** значення getter-ів, правила setter-ів (межі й помилки), заморожений
    dataclass, рівність, впорядкування, `__str__`/`__repr__`, формули підтипів, відповідність
    протоколу, поведінку програми (звіт, код завершення).
18. **`pytest`** запускає перевірки поведінки, **`ruff`** перевіряє стиль і типові помилки,
    **wheel** доводить, що пакет збирається й працює в чистому середовищі.
19. **Крайові випадки:** порожній вхід (лише заголовок і порожній файл), нуль і межа порога,
    дублікати, хибний тип, від'ємне, `nan`/`inf`, відсутні й зайві поля, текст із комою,
    не-UTF-8, недоступний вихідний файл.
20. **У REPORT декларують:** варіант, класи, поля й формули, правила setter-ів, порівняння
    старого й нового результату, версії інструментів, команди, коди завершення, результати CI,
    таблицю Issues/PR і внесок ШІ.

## 13. Висновки

Словникові записи лабораторної № 6 замінено об'єктною моделлю: `Training` із перевіреними
властивостями, підтипами `Running`/`Cycling` з різними формулами `load()`, незмінним
підсумком-dataclass і протоколом `Workout`, через який `analysis` працює без перевірок типів.
Зовнішній звіт лишився сумісним (доведено тестом і кроком CI), додано 69 тестів (разом 126), чистий
`ruff` і wheel із двома CLI. Модель і протокол стануть основою для подальших розширень (нових
підтипів без змін аналізу).
