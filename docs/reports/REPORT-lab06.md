## 2. Мета роботи

Створити невеликий пакет, який читає CSV через `csv.DictReader` (UTF-8), перетворює поля на
типізовані значення, обчислює показники за списком, словником і множиною, формує детермінований
текстовий звіт, записує його через `with` і має CLI, тести `pytest`, перевірку `ruff` і збірку
wheel. Досягнуто **рівня 3**; завдання із зірочкою (потокове читання, вимірювання пам'яті) не
виконувалося.

## 3. Формат CSV

Заголовок: `date,kind,duration,distance,pulse` (рівно ці стовпці, порядок будь-який).

| Стовпець | Тип у програмі | Правило |
| --- | --- | --- |
| `date` | `datetime.date` | ISO `РРРР-ММ-ДД` |
| `kind` | `str` (після `strip`) | непорожнє |
| `duration` | `int` | `>= 0` |
| `distance` | `float` | скінченне, `>= 0` |
| `pulse` | `int` | `>= 0` |

Файл `data/input.csv` (7 записів): є дубльований вид (`Біг` тричі), граничний запис
`duration = 45` (входить у відбір), `44`/`40`/`30`/`25` (не входять), текстове поле з комою
`"Силове, зал"`, нульова дистанція.

```text
date,kind,duration,distance,pulse
2026-09-01,Біг,45,7.50,148
2026-09-02,Велосипед,90,28.40,132
2026-09-03,Плавання,30,1.20,125
2026-09-04,"Силове, зал",60,0.00,118
2026-09-05,Біг,50,8.10,152
2026-09-06,Ходьба,40,3.40,102
2026-09-07,Біг,25,4.00,160
```

**Правило порожнього входу:** файл лише із заголовком — коректний порожній набір (`[]`, звіт із
нулями й рядками «немає …»); файл без заголовка (0 байтів) — `DataError`. Ідентичні рядки не
видаляються. Константа порога `MIN_DURATION = 45` задається в `analysis.py` і змінюється
параметром CLI `--min-duration`.

## 5. Перетворення даних

Читання: `path.open("r", encoding="utf-8", newline="")` + `csv.DictReader` (ручного `split(",")`
немає — він розрізав би `"Силове, зал"`). `DictReader` повертає лише рядки, тому на межі входу
(`parse_row`) виконується перетворення: `date.fromisoformat`, `int`, `float`, `strip`.

| Структура | Де | Навіщо |
| --- | --- | --- |
| список | `list[Record]` | зберігає порядок і дублікати |
| словник | `distance_by_kind` | зіставлення «вид → сума км» |
| множина | `unique_kinds` | унікальні види |
| comprehensions | `select_long` (list), `unique_kinds` (set), `distance_by_kind` (dict) | один прозорий відбір/перетворення |

Складніша логіка (перевірки полів із різними повідомленнями) залишена в звичайних функціях і
циклі `for` у `load_records`, де comprehension був би нечитабельним.

## 6. Функції

```python
def make_summary(records, *metrics: str, min_duration: int = MIN_DURATION, **labels: str) -> dict[str, float]
```

- `*metrics` — кортеж назв числових полів (`duration`, `distance`, `pulse`);
- `min_duration=45` — типове значення з незмінним числом (не змінюваний об'єкт — тому немає
  прихованого стану між викликами; тест `test_make_summary_is_repeatable`);
- `**labels` — словник підписів: `duration="Тривалість, хв"`.

```python
make_summary(records, "duration", "distance", duration="Тривалість, хв")
# {'count': 4.0, 'Тривалість, хв': 245.0, 'distance': 44.0}
```

Невідома метрика → `ValueError`; підпис для незапитаної метрики → `ValueError`; якщо всі записи
відсіяно, метрики мають `0.0`.

## 7. Алгоритм аналізу

1. `select_long` — список записів із `duration >= 45` (початковий порядок).
2. `unique_kinds` — множина видів **усіх** записів; у звіті сортується за алфавітом.
3. `distance_by_kind` — словник сум за видом **для відібраних записів**; ключі відсортовано, тому
   звіт не залежить від порядку рядків у файлі (тест із перемішаним входом). Порожній вхід →
   порожній словник.
4. `average_pulse` — середнє за **усіма** записами; для порожнього списку `0.0`.
5. `longest_workout` — максимум за `(duration, раніша дата)`; за повної рівності — перший запис;
   для порожнього списку `None`.

Результат на контрольних даних (звірено вручну): відібрано 4 з 7; сума тривалості 245; дистанція
44.00; Біг 15.60, Велосипед 28.40, «Силове, зал» 0.00; середній пульс `937 / 7 = 133.86`.

## 8. Обробка помилок

Усі очікувані помилки — `DataError` з номером рядка й назвою поля; першопричина зберігається
(`raise ... from error`). Голого `except` немає; `except Exception` застосовано лише на межі CLI.

| Ситуація | Повідомлення | `__cause__` |
| --- | --- | --- |
| відсутній файл | `Не вдалося прочитати файл: …` | `OSError` |
| не UTF-8 | те саме | `UnicodeDecodeError` |
| немає заголовка | `Файл порожній: відсутній заголовок CSV` | — |
| відсутній/зайвий стовпець | `Некоректний заголовок CSV (відсутні стовпці: pulse)` | — |
| хибне число | `Рядок 2: поле duration має бути цілим числом` | `ValueError` |
| від'ємне | `Рядок 2: поле distance не може бути від'ємним` | — |
| `nan`/`inf` | `Рядок 2: поле distance має бути скінченним числом` | — |
| хибна дата | `Рядок 2: поле date має бути датою РРРР-ММ-ДД` | `ValueError` |
| порожній текст | `Рядок 2: поле kind порожнє` | — |
| відсутнє значення (короткий рядок) | `Рядок 2: відсутнє значення поля pulse` | — |
| зайве значення | `Рядок 2: забагато полів` | — |
| помилка запису звіту | `Не вдалося записати звіт: …` | `OSError` |

Номер рядка — фізичний (`reader.line_num`): порожні рядки пропускаються, але нумерація не
зсувається (тест `…after_blank_line`).

**Коди завершення CLI:** `0` — успіх; `2` — очікувана помилка даних і помилки аргументів
(`argparse`); `1` — неочікувана помилка. Повідомлення виводиться в `stderr` з явним UTF-8
(`reconfigure`), traceback очікуваної помилки не показується.

## 15. Відповіді на контрольні питання

1. **`pyproject.toml`** описує пакет: назву, версію, `requires-python`, залежності, CLI-скрипт і
   налаштування інструментів (pytest, ruff).
2. **Віртуальне середовище** ізолює залежності проєкту від системного Python і відтворюється за
   `pyproject.toml`.
3. **`newline=""`** передає керування роздільниками рядків модулю `csv`, щоб він коректно
   обробляв переноси всередині полів у лапках.
4. **`DictReader` без перетворення** повертає рядки (`str`) для всіх значень (а для відсутніх —
   `None`).
5. **`split(",")`** не знає лапок: розріже `"Силове, зал"` на два поля й не обробить переноси
   рядка.
6. **Список** зберігає порядок і повтори; **словник** — пари «ключ → значення»; **множина** —
   унікальні значення без гарантованого порядку.
7. **Comprehension** зрозуміліший для одного прозорого відбору/перетворення; складна логіка з
   кількома умовами чи побічними ефектами краще читається у звичайному циклі.
8. **`*args`** — кортеж позиційних аргументів, **`**kwargs`** — словник іменованих.
9. **Змінне значення за замовчуванням** (`[]`, `{}`) створюється один раз і поділяється між
   викликами, тому накопичує стан; типове значення має бути незмінним (`0.0`, `None`).
10. **`raise ... from error`** записує початкову помилку у `__cause__`, тож у діагностиці видно
    і пояснення, і першопричину.
11. **Поділ на модулі** дає змогу тестувати кожен крок окремо (аналіз без файлів, звіт без CSV) і
    міняти один без правок інших.
12. **`with`** гарантує закриття файла після блоку, навіть якщо виник виняток.
13. **Детермінований звіт** однаковий для однакових даних незалежно від порядку рядків чи
    запуску, тому його можна порівнювати з еталоном.
14. **Порожній CSV:** лише заголовок (порожній набір), відсутність заголовка (помилка), нулі й
    «немає» у звіті, відсутність винятків і ділення на нуль.
15. **Тест поведінки** перевіряє видимий результат (звіт, значення, коди), а перевірка
    внутрішньої реалізації прив'язується до назв змінних і ламається за рефакторингу.
16. **`pytest`** знаходить файли `test_*.py` або `*_test.py`, функції й методи `test_*`.
17. **`ruff check`** — стиль і типові помилки (правила E, F, W, B, UP, I); `ruff format --check`
    — форматування без змін файлів.
18. **Коди CLI:** `0` — успіх; `2` — очікувана помилка даних (і помилки аргументів); `1` —
    неочікувана помилка.
19. **У CI** тести перевіряють поведінку, аналізатор — якість, пакетування — що пакет збирається й
    ставиться в чисте середовище; жодне не замінює інших.
20. **У REPORT декларують:** варіант і поля CSV, пороги й константи, правила порожнього входу,
    очікуваний звіт, коди завершення, команди, версії інструментів, результати CI.

## 16. Висновки

Створено модульний Python-пакет із типізованим завантаженням, чіткими помилками, детермінованим
звітом, CLI, 57 тестами, чистим `ruff` і wheel, який встановлюється в окреме середовище. Модулі
`loader`, `analysis`, `reporting`, `errors`, `cli` та словникові записи стануть основою для
лабораторної № 7, де записи перетворюються на об'єкти з властивостями й підтипами.
